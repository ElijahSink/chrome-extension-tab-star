Targeting the status field

TabStar Status appends a short piece of text from a web page to the tab group name, for example ABC-123 - In Progress. You tell it which text by giving a CSS selector for the element that holds the status. This page explains how to find a selector that keeps working.

What a CSS selector is

A CSS selector is the address of one element on a web page. Web developers use selectors to style elements; TabStar Status uses one to find the element whose text it should copy into the group title.

SelectorReads as
#status-valthe element with id="status-val"
[data-testid="header-state"]the element whose data-testid attribute equals header-state
input[aria-label="State Field"]an <input> whose aria-label equals State Field
.gh-header-meta .Statean element with class State inside one with class gh-header-meta

The extension takes the first matching element that has any text, trims it, and appends it to the group title after - . For inputs and dropdowns it uses the current value.

Rule name vs. tab group title

Rule Name is only a label in the popup list. Tab Group Title is what the group is actually called; $1, $2… insert the parts of the URL you wrapped in parentheses in the regex. Plain text gives every matching tab one fixed group.

1. Try a preset first

The popup has a Start from a preset menu for Jira, GitHub, GitLab, Azure DevOps and ServiceNow. A preset fills in the URL regex, group name template and selector. Presets marked (unverified) are best-effort starting points: open a matching page and click Test on Current Tab to confirm they work for your instance.

2. Find the element in DevTools

  1. Open the page that shows the status (the ticket, pull request, incident, and so on).
  2. Right-click the status text or badge and choose Inspect. DevTools opens with the element highlighted.
  3. If the highlighted element is a tiny inner <span>, look one or two levels up for a parent with a stable identifying attribute.
  4. Right-click the element in the Elements panel and choose Copy › Copy selector as a starting point, then simplify it (see below).

3. Prefer stable attributes

Generated class names such as .css-1x9kq2 change on every deploy. Choose, in this order:

AttributeExample selector
data-testid / data-test-id[data-testid="header-state"]
id#status-val
aria-labelinput[aria-label="State Field"]
Semantic class names.gh-header-meta .State
Attribute suffix matching helps when ids are prefixed: select[id$=".state"] matches incident.state, problem.state and so on.

4. Verify in the Console

Paste your selector into the DevTools Console to see exactly what the extension will read:

document.querySelector('[data-testid="header-state"]').textContent.trim()

If the status lives in an <input> or <select>, the extension uses the input's value or the selected option's text automatically. In the console use .value instead.

5. Add fallbacks

Separate several selectors with commas. They are tried in the order written; the first one that finds an element with non-empty text wins. Put the most specific first and avoid a generic last resort such as .badge: pages often contain other badges (GitLab shows a "Beta" label, for example) that would be read when the specific ones miss. This is how the Jira preset covers Cloud and Data Center in one rule: 

[data-testid="issue.views.issue-base.foundation.status.status-field-wrapper"] button, #status-val

Reading more than one thing

A rule can have several status fields. Each reads one element; the values are joined with · . The GitLab merge request preset uses two fields to show the MR state and its pipeline:

FieldSelectorKeep onlyLabelReads
1.detail-page-header .gl-badge-contentOpen
2.mr-pipeline-title#\d+\s+(\S+)CICI passed

Result: www!42 - Open · CI passed.

Keep only is a regex applied to the element's text; with parentheses, only that part is kept. The pipeline widget says "Pipeline #18395789 passed", and #\d+\s+(\S+) keeps the word after the number. Label is a plain prefix. A field whose element never appears is left out.

6. Test, then save

In the popup, click Test on Current Tab. Nothing is grouped. The result shows the group title the rule would produce, the status text the selector found, Read from (which element supplied it) and a preview of the final title. If you see:

ResultMeaning
regex did not matchThe URL regex does not match the current URL or tab title. Check escaping (\. for dots).
access was not grantedYou declined site access. Click Test again and allow it.
matched no element within 3 secondsThe selector is wrong, or the element renders very late. Re-inspect and try a parent element.
matched N element(s) but none had any textYou selected a wrapper or an icon. Try the parent, or the inner element that holds the words.
"Keep only" regex did not matchThe raw element text is shown; adjust the regex to it.

Keeping titles short

Chrome renders a tab group title on one line and truncates it when the tab strip is crowded, cutting off the end, which is where the status lives. The popup's Max group title length setting shortens the base name instead and always keeps the status:

SettingTitle
0 (no limit)perimeterx-lambda-at-edge pipeline #18395616 - Blocked
32perimeterx-lambda-at-… - Blocked
20perimeter… - Blocked

The base is never cut below 8 characters, so ticket keys like ABC-123 stay whole even if that means the title exceeds the limit with a very long status. Limits below 12 are raised to 12. Changing the setting re-titles all open groups. Short templates and labels help too: $1 !$2 beats $1 merge request #$2.

Things to know

  • Frames. The reader searches the main page and every same-origin iframe, so classic ServiceNow forms work.
  • Live updates. After the first read the extension watches the page. Changing the status without reloading also renames the group.
  • Timing. On load the reader waits up to 10 seconds for the element to appear. The Test button waits 3 seconds.
  • Permissions. The extension only reads sites you explicitly grant. Each rule stores the origin you entered, and the prompt appears when you save or test.
